# ADR-005: Migrar de Auto-Instanciação para Factory com Injeção de Dependência


**Supersedes:** Decisão inicial de auto-instanciação no construtor de `VideoPipeline`

## Contexto

Na versão original, `VideoPipeline.__init__` instanciava todos os 7 componentes
pesados diretamente, sem parâmetros:

```python
def __init__(self):
    self.detector = YoloDetector()       # carrega modelo YOLO do disco
    self.ball_detector = BallDetector()  # carrega modelo YOLO do disco
    self.jersey_reader = JerseyReader()  # carrega modelo YOLO do disco
    self.ball_event_detector = BallEventDetector()
    self.kinematic_analyzer = KinematicAnalyzer()
    self.clip_writer = ClipWriter()
    self.color_extractor = ColorExtractor()
```

Problemas identificados ao tentar escrever testes unitários para `VideoPipeline`:
1. Instanciar `VideoPipeline()` carregava 3 modelos YOLO (~1GB RAM, ~10s de inicialização)
2. Os testes usavam `patch.object(VideoPipeline, "__init__", lambda self: None)` + setagem
   manual de atributos — frágil e dependente de conhecimento dos internos da classe
3. Impossível substituir, por exemplo, `YoloDetector` por uma implementação de teste
   sem modificar o código-fonte

Esta decisão foi inicialmente adiada por "simplicidade", mas tornou-se insustentável
quando a suite de testes começou a travar em CI por timeout de carregamento de modelos.

## Decisão

`VideoPipeline.__init__` passa a receber todas as dependências como parâmetros.
`PipelineFactory.create()` centraliza o conhecimento de como instanciar e injetar
cada componente concreto.

Código de produção usa `PipelineFactory.create()`.
Código de teste usa `VideoPipeline(detector=MagicMock(), ...)` diretamente.

## Consequências

**Benefícios:**
- Testes unitários instantâneos: `VideoPipeline(detector=MagicMock(), ...)` sem carregar YOLO
- DIP satisfeito: `VideoPipeline` depende de `IDetector`, não de `YoloDetector`
- Ponto único de montagem: trocar qualquer componente é feito em `PipelineFactory`
- Facilita A/B de detectores (ex: testar YOLOv9 sem alterar o pipeline)

**Custos:**
- Assinatura do construtor cresceu (8 parâmetros)
- Código que chamava `VideoPipeline()` diretamente precisa migrar para `PipelineFactory.create()`
- Developer precisa conhecer a existência da Factory para instanciar o pipeline corretamente
