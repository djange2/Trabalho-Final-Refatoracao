# ADR-004: Aplicar Padrão Strategy para Extração de Cor de Camisa



## Contexto

O pipeline precisa extrair a cor predominante do torso de um jogador para dois
fins distintos com requisitos opostos:

1. **Fast Scan** — identifica candidatos na varredura inicial: exige precisão
   (K-Means isola melhor a cor real da camisa separando fundo verde do gramado)
2. **Tracking** — confirma identidade durante rastreamento: exige velocidade
   (chamado a cada `OCR_INTERVAL` frames para todos os jogadores do lote)

A versão original misturava os dois algoritmos como métodos privados
`_extract_core_color` e `_color_distance` diretamente em `VideoPipeline`,
violando SRP: o orquestrador do pipeline não deveria conhecer detalhes de
processamento de imagem.

Além disso, `ColorExtractor` (K-Means) era instanciado no construtor mas
**nunca chamado** — o pipeline usava `_extract_core_color` (cv2.mean) inline,
criando código morto e confusão de responsabilidades.

## Decisão

Extraímos o protocolo `IColorExtractor` com dois implementadores concretos:
- `MeanColorExtractor`: usa `cv2.mean` — O(n) nos pixels, padrão para tracking
- `KMeansColorExtractor`: usa K-Means — mais preciso, para identificação inicial

`VideoPipeline` recebe a estratégia via injeção de dependência no construtor.
`PipelineFactory` injeta `MeanColorExtractor` por padrão.

## Consequências

**Benefícios:**
- `VideoPipeline` não conhece o algoritmo específico (OCP satisfeito)
- Trocar a estratégia não requer modificar o pipeline (ex: injetar K-Means para fast_scan)
- Testabilidade: mock trivial de `IColorExtractor` nos testes unitários
- Elimina código morto (`ColorExtractor` não usado no pipeline)

**Custos:**
- Uma classe a mais por estratégia (complexidade de navegação leve)
- Developer precisa saber qual estratégia usar em cada contexto
