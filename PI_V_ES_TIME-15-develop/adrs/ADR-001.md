# ADR-001: Adotar Monolito Modular como Arquitetura Macro



## Contexto

O sistema processa vídeos de futebol para gerar clipes de jogadores específicos.
A equipe tem 4 membros e ciclo de desenvolvimento de 1 semestre. Latência aceitável
é de minutos por vídeo (processamento offline), não milissegundos. Infraestrutura
disponível é um único servidor com GPU.

## Decisão

Adotamos monolito modular: um único processo Python com módulos internos
bem delimitados (`ml/detector`, `ml/scripts/*`, `backend/app/*`), comunicando-se
por chamadas diretas de função — sem HTTP entre módulos de ML, sem filas,
sem processos separados para detecção e tracking.

## Consequências

**Benefícios:**
- Deploy trivial (um processo, sem orquestração de containers)
- Depuração direta (stack trace único do vídeo até o clipe)
- Latência zero entre componentes internos (detector → tracker → OCR em memória)
- Adequado ao tamanho e maturidade da equipe

**Custos:**
- Escalabilidade horizontal restrita a nível de thread (já mitigada pelo threading.local no VideoPipeline)
- Um bug crítico pode derrubar todo o pipeline
- Difícil escalar componentes individualmente (ex: escalar só o OCR)
